# The skip REASONS this qualification accepts.
#
# One regular expression per line, matched against the reason a case states
# for not running. A skip whose reason matches NONE of these FAILS the
# aggregate, and so does a skip that states no reason at all.
#
# This is a QUALIFICATION BOUNDARY, not a measurement: it says which reasons
# are legitimate in this environment. It carries no count, and it does not
# change when the number of tests changes.
#
# EVERY CLASS HERE NEEDS EVIDENCE FROM THIS ENVIRONMENT. A runner that
# provides a capability must not have a class that tolerates its absence:
# that turns "the tool disappeared from the image" into a green run.
#
# If a class becomes required coverage, the fix is to PROVISION the
# capability on the runner, not to keep accepting the skip.

# The official DSH Optional-bundle installation is not provisioned in the
# runner environment. The case says which packages it was looking for.
BLOCKED: no provisioned official DSH .* Optional-bundle installation

# The real `fd`/`fdfind` integration cannot run without the binary. The
# ubuntu-latest image does not ship it; a machine that has it runs the case.
no fd/fdfind on PATH

# DELIBERATELY ABSENT: the POSIX-only guards.
#
# `mkfifo is POSIX-only` and `no /dev/full` are the reasons a case gives on a
# host that LACKS those POSIX facilities. The CI runner is Linux and provides
# them, so a skip for either reason means the environment changed under us.
# Accepting them here would report that change as a healthy run; leaving them
# out makes it FAIL, which is the point.

# The Darwin KERNEL primitives cannot exist on Linux: the seat is an O_EXLOCK
# file and process identity is libproc. The Linux runner must NOT provide
# them, so this class is the platform boundary itself, not a capability that
# disappeared from the image. The real-kernel positive and negative evidence
# is recorded from macOS; the macOS product path is owned by later PRs.
Darwin kernel seats require macOS
Darwin kernel process identity requires macOS

# The schema 2 registry publication, the account-home Host seat dispatch and
# the Darwin detached managed-start fallback are the macOS side of the local
# split backend (PR-2). Their contracts are executed and recorded on the macOS
# product lane; the Linux runner sees the platform boundary skip, and the
# Linux schema 1/abstract-seat side runs for real here.
Darwin libproc identity requires macOS
the macOS classifier requires the real libproc identity
Darwin file seats require macOS
Darwin schema 2 requires the real libproc identity
the real Darwin detached fallback requires macOS

# The macOS daemon management commands (PR-3) drive the schema-2 kernel
# identity and the Darwin admin O_EXLOCK file seat. The real-kernel evidence is
# recorded on the macOS product/smoke lanes; the Linux runner sees the platform
# boundary skip and runs the whole Linux systemd side for real here.
Darwin kernel identity and file seats require macOS
